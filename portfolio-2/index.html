Перед началом

Что должно получиться

  • Над таймлайном — кнопки фильтров: «Все» и не меньше двух категорий ваших проектов.
  • Нажатая кнопка подсвечена, «Все» показывает все записи.
  • Все проекты хранятся в файле data.js. Записи таймлайна и карточки собираются из него — в index.html их больше нет.
  • Чтобы добавить проект, достаточно добавить одну запись в data.js.
  • Изменения сохранены на GitHub через GitHub Desktop: не меньше 5 коммитов с понятными описаниями.
  • Сайт обновлён по тому же адресу, создан релиз v2.

Что понадобится

  • Готовое задание 1: сайт по адресу ваш-логин.github.io и релиз v1.
  • VS Code и браузер: Chrome, Edge или Firefox.

Часть 1

GitHub Desktop

В первом задании вы загружали файлы на GitHub перетаскиванием. Для одного раза это удобно, для постоянной работы — нет. GitHub Desktop — программа, которая связывает папку на компьютере с репозиторием на GitHub: показывает, что вы изменили, и отправляет изменения одной кнопкой.

Каждое сохранённое изменение называется коммитом. Это точка в истории проекта с описанием, что изменилось, — к ней всегда можно вернуться.

Шаг 1Установите GitHub Desktop

  1. Скачайте программу с desktop.github.com и установите. После установки она откроется сама.
  2. Нажмите Sign in to GitHub.com. Откроется браузер: войдите в свой аккаунт GitHub и подтвердите доступ (Authorize desktop). Вернитесь в программу.
  3. На экране Configure Git оставьте имя и почту из аккаунта и нажмите Finish.

Подсказка

Если окно входа не появилось, войдите вручную: File → Options → Accounts → Sign in. На macOS — GitHub Desktop → Settings → Accounts.

Шаг 2Скачайте репозиторий на компьютер

  1. Выберите File → Clone repository…
  2. На вкладке GitHub.com выберите ваш-логин/ваш-логин.github.io.
  3. В поле Local path — куда положить папку. Предложенный вариант (Документы\GitHub\ваш-логин.github.io) подойдёт. Нажмите Clone.

Клонировать — значит скачать копию репозитория, которая помнит, откуда она. С этого момента работайте только в этой папке. Открыть её в VS Code можно прямо из GitHub Desktop: кнопка Open in Visual Studio Code (или Repository → Open in Visual Studio Code).

Частая ошибка

Если после первого задания вы что-то меняли в старой папке portfolio и не загрузили на GitHub, скопируйте эти файлы в новую папку с заменой. Старую папку переименуйте, например, в portfolio-old — чтобы случайно не править не тот файл.

Шаг 3Сделайте первый коммит

  1. В VS Code поменяйте подпись под именем (class="tagline") — например, допишите «и JavaScript». Сохраните файл.
  2. В GitHub Desktop слева, на вкладке Changes, появится index.html, а справа — что изменилось: красным — удалённые строки, зелёным — добавленные.
  3. Внизу слева, в поле Summary, коротко опишите изменение: «Обновлена подпись». Нажмите Commit to main.
  4. Нажмите Push origin вверху окна — коммит уйдёт на GitHub. Через 1–2 минуты изменение появится на сайте.

Commit — сохранить изменения в истории на вашем компьютере. Push — отправить их на GitHub. Пока вы не нажали Push, на сайте ничего не изменится.

Проверка

На сайте новая подпись, а на вкладке History в GitHub Desktop — ваш коммит.

Подсказка

Делайте коммит после каждого законченного шага: «Подключён script.js», «Кнопки фильтров», «Проекты в data.js». Описание пишите так, чтобы через месяц было понятно, что изменилось. «Правки» и «123» — не годятся.

Частая ошибка

Поправили файл прямо на github.com? Тогда перед следующим Push нажмите Fetch origin, а потом Pull origin — так правка с GitHub попадёт к вам на компьютер. Иначе GitHub отклонит Push.

Шаг 5Переменные

Перед первой вставкой

Когда вы впервые вставите код в консоль, браузер предупредит, что вставлять чужой код опасно, и попросит набрать allow pasting. Наберите эти слова, нажмите Enter и вставьте код ещё раз. И правда — вставляйте в консоль только код, которому доверяете, например из этой инструкции.

  • Переменная — имя для значения. const — значение нельзя поменять, let — можно. Пишите const, а let — только если значение будет меняться.
  • Строки — в кавычках, числа — без. true и false — «да» и «нет».
  • В строку в обратных кавычках `…` можно подставлять значения: ${count}. Обратная кавычка — на клавише Ё в английской раскладке.
  • // — комментарий: всё после него до конца строки JavaScript пропускает. Комментарии вроде // 7 показывают, что вы увидите в консоли.
  • Последней строкой консоль напишет undefined — это нормально: так она сообщает, что код ничего не вернул.

Шаг 7Функции

  • Функция — кусок кода с именем, который можно вызывать много раз. В скобках — параметры: значения, которые функция получает. return — что функция вернёт.
  • Стрелочная функция (=>) — короткая запись того же самого. Если тело функции — одно выражение, return и фигурные скобки можно не писать. В современном JavaScript стрелочные функции встречаются постоянно.
  • includes проверяет, есть ли значение в массиве, и возвращает true или false.

Шаг 8filter и map

Самый важный шаг этой части: filter и map понадобятся и в этом задании, и в следующем.

  • forEach — выполнить функцию для каждого элемента.
  • filter — оставить только элементы, для которых функция вернула true. Исходный массив не меняется — получается новый.
  • map — превратить каждый элемент во что-то другое: проект — в название, проект — в кусок HTML. Тоже получается новый массив.
  • join('') — склеить массив строк в одну строку.

Шаг 10Оформление кнопок

  • Кнопки не наследуют шрифт страницы сами — поэтому font: inherit.
  • border-radius: 999px — скругление больше высоты кнопки, получается «таблетка».
  • .is-active — класс выбранной кнопки, .is-hidden — класс скрытой записи. Сами по себе они ничего не делают: добавлять и убирать их будет JavaScript.

Шаг 11Логика фильтров

Замените всё содержимое script.js:

Разберём по строчкам:

  • document.querySelectorAll('.filter-btn') — найти на странице все элементы с классом filter-btn. Селекторы — те же, что в CSS.
  • button.addEventListener('click', () => { … }) — «когда по кнопке кликнут, выполни эту функцию».
  • button.dataset.filter — значение атрибута data-filter этой кнопки.
  • classList.remove и classList.add — убрать или добавить класс. Сначала снимаем подсветку со всех кнопок, потом подсвечиваем нажатую.

  • === — «равно», || — «или»: показать запись, если выбрано «Все» или у неё есть нужная категория.
  • classList.toggle('is-hidden', !show) — добавить класс, если второе значение true, и убрать, если false. ! — «не»: прятать, если показывать не нужно.
