Что такое React

В задании 2 вы сами писали renderTimeline: брали данные, превращали их в HTML, вставляли на страницу — и вызывали её заново после каждого клика. React делает то же самое, но за вас. Вы описываете, как выглядит страница при текущих данных, а когда данные меняются, React сам обновляет нужную часть.

Страница в React собирается из компонентов — функций, которые возвращают разметку. Шапка, профиль, запись таймлайна, карточка — у каждого компонента свой файл.

Код копируйте кнопкой Копировать — над каждым блоком написано, в какой файл его вставить. Если написано «весь файл» — замените всё содержимое файла.

Шаг 1Установите Node.js

React-проекты собираются специальными программами, и для них нужен Node.js — среда, которая запускает JavaScript на компьютере, а не в браузере. Вместе с ним ставится npm — программа, которая скачивает React и другие библиотеки.

  1. Скачайте с nodejs.org версию LTS (для Windows — Windows Installer (.msi)) и установите с настройками по умолчанию.
  2. Откройте папку сайта в VS Code — из GitHub Desktop кнопкой Open in Visual Studio Code.
  3. Откройте терминал: Terminal → New Terminal (Ctrl+`). Внизу появится панель для текстовых команд.
  4. Введите по очереди две команды, после каждой — Enter:
    Должны появиться номера версий, например v24.19.0 и 11.17.0.

Терминал — окно для текстовых команд: набрали команду, нажали Enter. Текст слева от курсора показывает, в какой папке вы находитесь, — он должен заканчиваться на ваш-логин.github.io.

Потом закройте терминал (значок корзины) и откройте новый.

export const делает переменную доступной другим файлам. Забирают её так: import { projects } from '../projects.js'. Фигурные скобки нужны, потому что из файла можно экспортировать несколько значений по имени, а export default — только одно, без скобок.

Шаг 10Запись таймлайна: props

  • Props — параметры компонента. Когда пишем <TimelineItem project={p} />, функция получает объект { project: p }. Фигурные скобки в параметрах — ({ project }) — достают из него project.
  • project.tag && <span…> — «если есть метка, покажи её». Если tag пустой, React ничего не нарисует.
  • project.card ? A : B — запись становится ссылкой, только если есть карточка. То же самое вы делали в задании 2.
  • href={`#project-${project.id}`} — значение атрибута собирается из шаблонной строки.
  • Кусок JSX можно сохранить в переменную, как content, и использовать дважды.

Часть 5

Состояние: useState

Состояние (state) — значения, которые меняются, пока человек пользуется страницей: выбранный фильтр, открытое меню, текст в поле поиска. Когда состояние меняется, React заново вызывает компонент и обновляет страницу. Вызвать функцию-компонент заново — это и есть «перерисовать».

Функции React, названия которых начинаются с use, называются хуками. Их вызывают в начале компонента, до return.

Шаг 13Кнопки фильтров

  • Компонент сам ничего не решает: какой фильтр выбран (active) и что делать при клике (onSelect), ему передают через props.
  • onClick={() => onSelect(f.id)} — обработчик клика прямо в разметке. Это замена addEventListener из задания 2.
  • className={…} — класс зависит от условия: у выбранной кнопки есть is-active.

Кнопки появятся в следующем шаге.

Шаг 14useState: выбранный фильтр

  • useState('all') создаёт состояние с начальным значением 'all' и возвращает пару: текущее значение и функцию, которая его меняет. Квадратные скобки раскладывают пару на две переменные: filter и setFilter.
  • <FilterBar active={filter} onSelect={setFilter} /> — кнопки получают текущий фильтр и функцию для его смены.
  • Клик по «Хобби» → setFilter('hobby') → React снова вызывает Timeline, теперь filter равен 'hobby' → visible считается заново → React обновляет на странице только то, что изменилось.

Сравните с заданием 2: там вы сами снимали и ставили классы кнопкам и вызывали renderTimeline. Здесь вы только меняете значение — остальное делает React. Даже подсветка кнопки обновляется сама, потому что className зависит от filter.

Проверка

Фильтры работают, нажатая кнопка подсвечена. Сделайте коммит «Фильтры на useState» и нажмите Push.

Часть 6

Эффекты: useEffect

Компонент должен только вычислять разметку. Но иногда нужно сделать что-то «снаружи»: сохранить данные в браузере, поменять заголовок вкладки, следить за нажатиями клавиш. Это называется побочным эффектом, и для него есть хук useEffect: код внутри выполняется после того, как React обновил страницу.

Шаг 15Запомните выбранный фильтр

  • localStorage — память браузера для сайта. Хранит строки по ключу и не стирается при перезагрузке. getItem читает, setItem записывает.
  • useState(localStorage.getItem('filter') || 'all') — начальное значение: сохранённый фильтр, а если его нет — 'all'.
  • useEffect(() => { … }, [filter]) — первый аргумент: что сделать. Второй — массив зависимостей: эффект запускается после первой отрисовки и потом каждый раз, когда изменилось что-то из массива. Здесь — когда сменился filter.

Подсказка

В режиме разработки (npm run dev) React специально запускает эффекты дважды, чтобы находить ошибки. Если поставите в эффект console.log и увидите сообщение два раза — это нормально. На опубликованном сайте эффект запускается один раз.

Проверка

Выберите «Хобби» и обновите страницу (F5) — «Хобби» по-прежнему выбрано. Сохранённое значение видно в Chrome: F12 → Application → Local Storage. Сделайте коммит «Фильтр запоминается».

Шаг 16Когда эффект не нужен

Частая ошибка — использовать useEffect, чтобы вычислить одно состояние из другого:

Это работает, но плохо: список хранится дважды, после клика React рисует страницу два раза — сначала со старым списком, потом с новым, — а в коде легко забыть обновить одну из копий. Правильно — вычислять значение прямо при отрисовке, как у вас в Timeline.jsx:

Правило: если значение можно вычислить из того, что уже есть, — вычисляйте его, а не храните в состоянии. useEffect нужен, только чтобы связать компонент с чем-то вне React: памятью браузера, заголовком вкладки, клавиатурой, сервером.

Если сборка не прошла, в терминале будет красное сообщение с именем файла и номером строки. Найдите эту строку и сравните с полным кодом.

Шаг 19Файл публикации

  1. Создайте в корне папку .github, в ней папку workflows, а в ней файл deploy.yml:
  2. Удалите папку old — старая версия больше не нужна.
  3. Сделайте коммит «Публикация через GitHub Actions» и нажмите Push.

Это инструкция для GitHub: при каждом push в main взять код, установить библиотеки (npm ci), собрать сайт (npm run build) и опубликовать папку dist. Файл взят из документации Vite.

Частая ошибка

Папка .github — с точкой, workflows — во множественном числе, расширение — .yml. В YAML важны отступы: копируйте файл целиком, ничего не выравнивая.

Шаг 20Включите публикацию через Actions

  1. На GitHub откройте свой репозиторий → Settings → Pages.
  2. В разделе Build and deployment, в поле Source, выберите GitHub Actions. Сохранять не нужно — настройка применяется сразу.

GitHub может предложить готовые варианты (Jekyll, Static HTML) — не выбирайте их: у вас свой файл. Сайт пока показывает прежнюю версию.

Шаг 21Объедините ветки

  1. В GitHub Desktop нажмите Current Branch и выберите main.
  2. В меню выберите Branch → Merge into current branch…, выберите react и нажмите Create a merge commit.
  3. Нажмите Push origin.
  4. На GitHub откройте вкладку Actions: там запуск «Deploy to GitHub Pages». Жёлтый кружок — идёт сборка, зелёная галочка — сайт опубликован. Обычно это занимает минуту-две.

Что видитеЧто проверить

  • Терминал открыт не в той папке. Откройте в VS Code именно папку сайта и запустите новый терминал.

  • Откройте консоль (F12): красная ошибка покажет файл и строку.

  • Путь в import не совпадает с файлом: имя, папка, регистр букв, расширение .jsx.

  • Компонент или функция используется, но не импортирована: проверьте строки import вверху файла.
Adjacent JSX elements must be wrapped
  • Компонент возвращает несколько элементов подряд: оберните их в <>…</>.

  • В JSX пишется className, а не class.
Each child in a list should have a unique "key" prop
  • У компонента внутри map нет key или ключи повторяются.
Таймлайн пустой, ни одна кнопка не выбрана
  • В памяти браузера остался фильтр, которого больше нет (например, после переименования категории). Нажмите «Все».

  • Нет файла .gitignore или он называется иначе. Создайте его (шаг 4) — node_modules пропадёт из списка.
Во вкладке Actions красный крестик
  • Откройте запуск и шаг с крестиком — там текст ошибки.
  • Ошибка в шаге Install dependencies — закоммичен ли package-lock.json?
  • Ошибка в шаге Build — выполните npm run build у себя и исправьте ошибку.
На сайте старая версия, README или 404
  • В Settings → Pages источник — GitHub Actions (шаг 20).
  • Ветки объединены и отправлены: в GitHub Desktop выбрана main, Push сделан.
  • В Actions зелёная галочка; обновите страницу с Ctrl+F5.
Нет картинок
  • Картинки лежат в public/images, пути в projects.js — images/…, регистр букв совпадает.
