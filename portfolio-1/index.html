Сайт-портфолио с таймлайном проектов

Вы сделаете личный сайт на HTML и CSS: фото, контакты, таймлайн ваших проектов и карточки с подробностями. А потом опубликуете его в интернете через GitHub Pages — бесплатно, по адресу вида ваш-логин.github.io.

Что получится

https://ваш-логин.github.io

Это живой пример: его можно прокручивать, а клик по записи в таймлайне ведёт к карточке проекта. Цветные прямоугольники — заглушки на месте ваших картинок. Код примера целиком — в конце инструкции.

Перед началом

Что должно быть на сайте

  • Шапка с меню: «Обо мне» и «Проекты».
  • Ваше фото, имя, короткая подпись о себе и контакты — минимум две ссылки.
  • Таймлайн: не меньше 6 записей, новые сверху. У каждой записи — дата, название и одно предложение описания.
  • Карточки проектов: не меньше 4. У каждой — картинка, описание и ссылка, если есть куда вести.
  • Клик по записи в таймлайне прокручивает к карточке этого проекта. Записи без карточки (например, курс) — просто текст.
  • На телефоне колонки встают друг под друга, и ничего не вылезает за край экрана.
  • Сайт открывается в интернете по адресу https://ваш-логин.github.io.

Что понадобится

  • Компьютер с Windows или macOS и браузер: Chrome, Edge или Firefox.
  • Электронная почта — для регистрации на GitHub.
  • Ваше фото и материалы о 6 или больше проектах. Что считать проектом — в шаге 3.

Как работать с инструкцией

Идите по шагам по порядку. Код копируйте кнопкой Копировать — над каждым блоком кода написано, в какой файл и куда его вставить. После каждого шага сохраняйте файл и смотрите на результат в браузере: так ошибку легко поймать сразу, а не искать потом во всём коде.

Часть 1

Подготовка

Шаг 1Установите редактор кода

Код можно писать хоть в Блокноте, но в редакторе кода удобнее: он раскрашивает теги разными цветами, сам закрывает скобки и подсказывает названия свойств.

Скачайте Visual Studio Code с сайта code.visualstudio.com и установите с настройками по умолчанию.

Подсказка

Интерфейс на русском: слева нажмите значок из четырёх квадратиков (Extensions, Ctrl+Shift+X), найдите Russian Language Pack и нажмите Install.

Шаг 2Создайте папку проекта

  1. Создайте папку portfolio — например, в «Документах».
  2. В VS Code выберите File → Open Folder… (Файл → Открыть папку) и откройте portfolio.
  3. Слева, в панели Explorer, наведите курсор на название папки и нажмите значок New File (листок с плюсом). Назовите файл index.html. Так же создайте style.css.
  4. Значком New Folder (папка с плюсом) создайте папку images.

Частая ошибка

Не создавайте файлы через «Создать → Текстовый документ» в Проводнике. Windows прячет расширения, и вместо index.html получится index.html.txt — браузер не поймёт, что это веб-страница.

Шаг 3Соберите материалы

Прежде чем писать код, подготовьте содержимое сайта — тогда в следующих шагах останется только вставлять его.

  • Фото для аватарки. Лучше квадратное, лицо по центру. Сохраните как images/avatar.jpg.
  • 6 или больше записей для таймлайна: месяц и год, название, одно предложение о том, что это было и какая у вас была роль.
  • 4 из них — проекты с картинкой: скриншот, фото результата, обложка. Сохраните картинки как images/project-1.jpg … images/project-4.jpg. Для каждого проекта — 1–2 предложения описания и ссылка, если есть: сайт, макет, видео, пост.

Что считать проектом. Учебные работы и курсовые, хакатоны и конкурсы, онлайн-курсы, хобби — рисунки, фото, видео, игры, всё, что вы сделали сами или в команде. Для таймлайна подойдёт всё, чем вы гордитесь или чему научились.

Частая ошибка

Имена файлов — только латиница, строчные буквы, без пробелов: project-1.jpg, а не Проект 1.JPG. На вашем компьютере Photo.JPG и photo.jpg — один и тот же файл, а на GitHub Pages — разные. Картинка будет видна у вас, но пропадёт на опубликованном сайте.

Подсказка

Фото с телефона весят 3–5 МБ, и сайт с ними грузится медленно. Уменьшите их на squoosh.app: ширина около 1200 пикселей, формат MozJPEG, качество 75–80. Картинка станет в 10–20 раз легче, а на глаз не изменится.

HTML — содержимое страницы

Как смотреть результат

Откройте папку portfolio в Проводнике и дважды щёлкните index.html — страница откроется в браузере. Дальше цикл такой: вставили код → сохранили файл (Ctrl+S) → обновили страницу в браузере (F5). На macOS вместо Ctrl — Cmd, вместо F5 — Cmd+R.

Что здесь что:

  • <!DOCTYPE html> — сообщает браузеру, что это современный HTML.
  • <html lang="ru"> — вся страница. lang подсказывает язык, чтобы браузер правильно переносил слова.
  • <head> — служебная часть, на странице её не видно. charset="UTF-8" — кодировка, без неё русские буквы превратятся в «кракозябры». viewport — чтобы на телефоне сайт не выглядел уменьшенной копией компьютерной версии. <title> — название во вкладке браузера. Первый <link> подключает шрифт Inter из Google Fonts, второй — ваш файл стилей style.css.
  • <body> — всё, что видно на странице. Внутри — <main> с двумя разделами (<section>): «Обо мне» и «Проекты».
  • <!-- … --> — комментарии, браузер их не показывает. В следующих шагах вы будете заменять каждый такой комментарий кодом.

Проверка

Откройте index.html в браузере. На странице только слово «Проекты», а во вкладке — «Имя Фамилия — портфолио». Так и должно быть.

Шаг 6Профиль и контакты

Замените комментарий <!-- ШАГ 6: профиль -->:

  • <img> — картинка, закрывающего тега у неё нет. src — путь к файлу, alt — описание для тех, кто не видит картинку, и на случай, если она не загрузилась.
  • <h1> — главный заголовок страницы, он один. <h2> и <h3> — заголовки поменьше.
  • <ul> — список, <li> — пункт списка.
  • mailto: в ссылке открывает почтовую программу, target="_blank" — открывает ссылку в новой вкладке.

Замените имя, подпись и ссылки на свои. Ненужный контакт удалите вместе с <li>…</li>, недостающий — добавьте по образцу.

Шаг 7Таймлайн

Замените комментарий <!-- ШАГ 7: таймлайн -->:

Каждая запись — это <article class="timeline-item"> с датой, названием и описанием. Записи бывают двух видов:

  • С карточкой. Всё содержимое обёрнуто в ссылку <a href="#project-coffee">. Клик по записи прокрутит страницу к карточке с id="project-coffee" — её вы сделаете в следующем шаге.
  • Без карточки — как хакатон и курс в примере. Просто текст, без <a>.

<span class="tag"> — необязательная метка рядом с названием: «Хакатон», «Курс», «В команде».

Подсказка

Сначала вставьте пример как есть и убедитесь, что всё работает. Потом замените тексты на свои. Чтобы добавить запись, скопируйте любой <article>…</article> целиком и вставьте рядом. Самые новые записи — сверху.

У каждой карточки есть id, и он должен точно совпадать со ссылкой в таймлайне, только без решётки: в таймлайне href="#project-cat" — у карточки id="project-cat". Придумывайте id латиницей, без пробелов: project- и короткое название.

Проверка

Сохраните файл и обновите страницу. Всё содержимое на месте, но выглядит как документ из 90-х: синие ссылки, огромные картинки. Это нормально — оформлением займёмся в части 3. Убедитесь, что фото и картинки проектов загрузились, а клик по записи в таймлайне прыгает к нужной карточке.

Частая ошибка

Вместо картинки — значок «сломанного» изображения? Сравните путь в src с настоящим именем файла, буква в букву: images/project-1.jpg — не image/, не .jpeg, не .png.

Часть 3

CSS — оформление

CSS описывает, как выглядят элементы. Правило состоит из селектора — кого оформляем — и свойств — как именно:

Точка перед именем выбирает элементы по классу (class="tagline"), решётка — по id, просто имя тега (h1) — все такие теги на странице. Весь код этой части вставляйте в style.css, каждый новый блок — в конец файла.

Шаг 9Цвета и основа

  • Переменные в :root. --accent: #f5b83d — это цвет, записанный один раз. Дальше в коде вместо него пишем var(--accent). Захотите другой акцент — поменяете одну строку, и он сменится на всём сайте. Цвет записан в формате #RRGGBB; подобрать свой можно, набрав в поисковике «color picker».
  • * выбирает все элементы. Браузер сам добавляет отступы заголовкам, абзацам и спискам — мы их обнуляем и дальше расставляем сами. box-sizing: border-box — чтобы рамка и внутренние отступы входили в ширину элемента, а не прибавлялись к ней.
  • padding-top: 64px у body — место под шапку, которую в следующем шаге закрепим сверху.

Проверка

Фон стал тёмным, шрифт сменился, ссылки больше не синие и не подчёркнутые.

Шаг 10Шапка

  • position: fixed закрепляет шапку: при прокрутке она остаётся на месте. top: 0 и left: 0 — в левом верхнем углу окна, z-index — поверх остального.
  • display: flex выстраивает содержимое в ряд, justify-content и align-items центрируют его по горизонтали и вертикали, gap — расстояние между пунктами меню.
  • rgba(20, 22, 31, 0.8) — тот же цвет, что у фона страницы, но с прозрачностью 0.8. backdrop-filter: blur размывает то, что проезжает под шапкой. Если поменяете --bg, поменяйте и здесь: первые три числа — это тот же цвет в формате RGB.
  • scroll-margin-top — отступ сверху при переходе по якорю, чтобы шапка не закрыла начало раздела.

Проверка

Прокрутите страницу — шапка остаётся наверху, текст под ней слегка размыт. Клик по «Проекты» плавно прокручивает к разделу.

Шаг 11Две колонки и профиль

  • display: flex у .about ставит профиль и таймлайн рядом. flex: 1 и flex: 1.5 — пропорции: таймлайну достаётся в полтора раза больше места.
  • max-width: 1100px и margin: 0 auto — на широком мониторе содержимое не растягивается во всю ширину и стоит по центру.
  • Круглое фото — это одинаковые ширина и высота плюс border-radius: 50%. object-fit: cover обрезает фото под круг, а не сплющивает его.

Проверка

Профиль слева, таймлайн справа, фото круглое, с цветной рамкой.

Шаг 12Таймлайн

Линия — это просто левая рамка блока .timeline. Кружки интереснее:

  • ::before создаёт «виртуальный» элемент в начале каждой записи. Текста у него нет (content: ''), но есть размер, рамка и скругление — получается кружок.
  • position: relative у записи делает её точкой отсчёта, а position: absolute у кружка позволяет поставить его в точное место относительно записи — даже за её левый край.
  • :has(a:hover) означает «запись, внутри которой ссылка под курсором». Так кружок заливается цветом при наведении — но только у записей с карточкой.

Проверка

Слева от записей — линия с кружками, кружки ровно на линии. При наведении на запись с карточкой подсвечиваются название и кружок, у записей без карточки — ничего.

Подсказка

Если кружок съехал — вы, скорее всего, поменяли толщину линии, отступ или размер кружка. Пересчитайте left по той же формуле: отступ + половина линии + половина кружка, со знаком минус.

Шаг 13Карточки проектов

  • Карточка — тоже flex-контейнер: картинка слева, текст справа.
  • overflow: hidden вместе с border-radius обрезают картинку по скруглённым углам карточки.
  • У картинки фиксированный размер 320 × 220, а object-fit: cover вписывает в него любую картинку без искажений — лишнее просто обрезается. flex-shrink: 0 не даёт картинке сжиматься, если текста много.
  • scroll-margin-top: 88px — при переходе из таймлайна карточка остановится чуть ниже шапки.

Проверка

Карточки на отдельном фоне, картинки одного размера. Клик по записи в таймлайне плавно прокручивает к карточке, и она не прячется под шапкой.

Шаг 14Версия для телефона

@media (max-width: 800px) — правила внутри срабатывают, только когда окно уже 800 пикселей. Колонки встают друг под друга, а картинка в карточке — над текстом.

Проверка

Сузьте окно браузера — примерно на 800px колонки должны перестроиться. Точнее проверить так: нажмите F12, затем Ctrl+Shift+M (или значок телефона в панели разработчика) и выберите модель телефона в списке сверху. Ничего не должно вылезать за край, страница не должна прокручиваться вбок.

Часть 4

Публикация на GitHub Pages

GitHub — сайт для хранения кода. Проект там называется репозиторием: это папка с файлами и историей всех изменений. GitHub Pages — бесплатный хостинг от GitHub: он берёт файлы из репозитория и показывает их как сайт.

Интерфейс GitHub на английском, поэтому ниже названия кнопок даны так, как они написаны на сайте.

Шаг 15Зарегистрируйтесь на GitHub

На github.com нажмите Sign up и следуйте подсказкам. Логин (Username) станет частью адреса сайта: логин pixel-fox → сайт pixel-fox.github.io. Выбирайте короткий, латиницей, строчными буквами — менять его потом неудобно.

Шаг 16Создайте репозиторий

  1. Справа вверху нажмите + → New repository.
  2. В поле Repository name введите ваш-логин.github.io — именно ваш логин, строчными буквами, с .github.io в конце. Например, pixel-fox.github.io.
  3. Оставьте Public: на бесплатном тарифе GitHub Pages работает только с публичными репозиториями.
  4. Нажмите Create repository.

Частая ошибка

Если имя репозитория не совпадает с логином — например, portfolio или с опечаткой, — сайт окажется по другому адресу или не откроется вовсе. Переименовать репозиторий можно в Settings → General → Repository name.

Шаг 17Загрузите файлы

  1. На странице нового репозитория нажмите ссылку uploading an existing file. Если при создании вы добавили README и этой ссылки нет — нажмите Add file → Upload files.
  2. Откройте папку portfolio в Проводнике, выделите index.html, style.css и папку images и перетащите их все вместе в окно браузера.
  3. Дождитесь, пока загрузятся все файлы, и нажмите зелёную кнопку Commit changes внизу страницы.

Частая ошибка

Перетаскивайте содержимое папки portfolio, а не саму папку. Иначе на GitHub всё окажется внутри portfolio/, и GitHub Pages не найдёт index.html. Правильно — когда index.html видно сразу на главной странице репозитория. И ещё: через кнопку choose your files папку выбрать нельзя, папку images — только перетаскиванием.

Шаг 18Включите GitHub Pages

  1. В репозитории откройте вкладку Settings, слева выберите Pages.
  2. В разделе Build and deployment: Source — Deploy from a branch, Branch — main и папка / (root). Нажмите Save. Если всё уже выбрано так — ничего не меняйте.
  3. Подождите 1–2 минуты и обновите страницу настроек. Сверху появится Your site is live at… со ссылкой. За публикацией можно следить во вкладке Actions.
  4. Откройте https://ваш-логин.github.io — это ваш сайт. Ссылку можно отправить кому угодно.

Проверка

На опубликованном сайте видны все картинки, работают меню и переходы из таймлайна к карточкам. Откройте сайт и с телефона.

Шаг 19Как обновлять сайт

Меняйте файлы на компьютере, как раньше, проверяйте в браузере, а потом:

  1. В репозитории нажмите Add file → Upload files.
  2. Перетащите изменённые файлы — файлы с тем же именем заменятся.
  3. Нажмите Commit changes — изменения отобразятся на сайте.

Мелкую правку можно сделать прямо на GitHub: откройте файл, нажмите значок карандаша (Edit), исправьте и нажмите Commit changes. Только не забудьте потом внести ту же правку в файл на компьютере — иначе при следующей загрузке она пропадёт.

Подсказка

Не видите изменений? Обновите страницу с Ctrl+F5 — браузер не возьмёт старую версию из памяти. Иногда GitHub Pages обновляется до 10 минут.

Если что-то не работает

Что видитеЧто проверить
404: «There isn't a GitHub Pages site here»
  • Имя репозитория — точно логин + .github.io.
  • index.html лежит в корне репозитория, а не в папке.
  • Файл называется index.html, строчными буквами.
  • После загрузки прошло хотя бы 2–3 минуты.
Сайт без оформления, просто текст
  • Файл называется style.css, лежит рядом с index.html и загружен на GitHub.
  • В <head> есть <link rel="stylesheet" href="style.css">.
У вас картинки есть, а на опубликованном сайте — нет
  • Регистр букв и расширение совпадают: Project-1.JPG и project-1.jpg для GitHub — разные файлы.
  • Папка images загружена на GitHub.
  • В пути прямой слеш /, а не обратный \.
Клик по записи в таймлайне никуда не ведёт
  • id карточки совпадает с href записи без #.
  • В id нет пробелов и русских букв, и он не повторяется на странице.
«Кракозябры» вместо русских букв
  • В <head> есть <meta charset="UTF-8">.
  • Файл сохранён в UTF-8 — это видно справа внизу в VS Code.
Вёрстка «поехала» после правки
  • Не потерялась ли закрывающая } в CSS или закрывающий тег в HTML. VS Code подсвечивает парные скобки и теги.
  • Сравните свой код с полным кодом в конце инструкции.
